Method 1: Browser Extension Recommended · Zero Command-Line · All OS

Use a lightweight browser extension to sync your existing muse.ai login session from your browser. No Python or terminal required.
Why an extension is required: The core session cookies have the httpOnly flag and cannot be accessed via web JavaScript (F12 document.cookie or bookmarklets). Only the browser extension cookies API has the privileges to read them.
1
Download & Unzip Extension
Unzip to a persistent directory, e.g. ~/muse2api-extension.
⬇ Download muse2api-extension.zip
2
Load Extension in Browser
For Chrome / Edge / Brave / Chromium browsers:
  1. Navigate to chrome://extensions
  2. Enable Developer mode in top right
  3. Click Load unpacked in top left
  4. Select the unzipped extension folder
3
Log in to muse.ai, then click extension to import
Open https://muse.ai/ in your browser and sign in (until the chat UI is visible). Then click the extension icon in your browser toolbar, enter the two values below, and click "Read and Import".

Method 2: Manual Cookie Copy Zero Install · Fallback

If you prefer not to install the extension, you can extract cookies manually using the Network tab Request Headers in DevTools (Console cannot read httpOnly cookies, but Network headers show all of them).
  1. Open and log in to https://muse.ai/ in your browser.
  2. Press F12 to open DevTools, switch to Network panel.
  3. Press F5 to refresh page and populate requests.
  4. Click any muse.ai request in the list.
  5. Navigate to Headers → scroll to Request Headers.
  6. Find the line starting with cookie: and copy the entire value (starting from hatch_sess= to the end).
  7. Paste it into Method 3 input below and click Import.
Notice: Use Request Headers cookie:, not "Response Headers". Response headers only contain partial cookies.

Integration Documentation

Standard OpenAI-compatible API format. Simply specify base_url and api_key.
BASE URL：—

1. Available Models

Model IDPurposeEndpoints
muse-sparkText & Code Chat (Streaming supported)POST /v1/chat/completions
POST /v1/responses
muse-imageText-to-Image & Image EditingPOST /v1/images/generations
muse-videoText-to-Video & Image-to-VideoPOST /v1/videos → GET /v1/videos/{id}
These three reflect muse.ai capabilities: Muse Spark (chat/code), Muse Image (text-to-image), Muse Video (video). Because muse.ai routes dynamically without model selectors, incoming model names like gpt-4o, claude-sonnet-4, or dall-e-3 are mapped automatically.

2. Chat / Code Completions

Copy# Non-streaming
curl -X POST "BASE/v1/chat/completions" \
  -H "Authorization: Bearer $MUSE2API_KEY" \
  -H "Content-Type: application/json" \
  -d '{"model":"muse-spark","messages":[{"role":"user","content":"Write a Python quicksort algorithm"}]}'

# Streaming: set "stream": true for standard SSE chunks (data: {...} / data: [DONE])

3. Image Generation (curl)

Copycurl -X POST "BASE/v1/images/generations" \
  -H "Authorization: Bearer $MUSE2API_KEY" \
  -H "Content-Type: application/json" \
  -d '{"prompt":"A cyberpunk Shiba Inu wearing an astronaut helmet","size":"1:1","response_format":"url"}'

# Response
{"created":1790148495,"data":[{
  "revised_prompt":"A cyberpunk Shiba Inu wearing an astronaut helmet",
  "url":"http://your-server:18610/v1/media/xxxx.webp",
  "kind":"image","bytes":23860}]}

# url is an absolute link, ready for rendering/download; /v1/media/* is public.
# For base64 output, pass "response_format": "b64_json".

4. Video Generation (curl, Async)

Copy# 1. Create async task
curl -X POST "BASE/v1/videos" \
  -H "Authorization: Bearer $MUSE2API_KEY" \
  -H "Content-Type: application/json" \
  -d '{"prompt":"A small kitten walking on grass","duration":5,"size":"16:9"}'
# → {"id":"task_xxx","status":"queued"}

# 2. Poll task status
curl "BASE/v1/videos/task_xxx" -H "Authorization: Bearer $MUSE2API_KEY"
# → {"status":"succeeded","result":{"url":"/v1/media/xxx.mp4"}}

5. Python (OpenAI SDK Compatible)

Copyfrom openai import OpenAI
import time

client = OpenAI(base_url="BASE/v1", api_key="m2a_...")

# Generate Image
r = client.images.generate(model="muse-image", prompt="A cyberpunk Shiba Inu wearing an astronaut helmet")
print(r.data[0].url)

# Generate Video (Async native endpoint)
import requests
t = requests.post("BASE/v1/videos", json={"prompt":"kitten walking","duration":5},
                  headers={"Authorization":"Bearer m2a_..."}).json()
while True:
    s = requests.get(f"BASE/v1/videos/{t['id']}",
                     headers={"Authorization":"Bearer m2a_..."}).json()
    if s["status"] in ("succeeded","failed"): break
    time.sleep(5)
print(s)

Autonomous agent modes with tool/function callstool_calls / function calling⚠️ Unsupported
Note on Tool Calling (Function Calling):
muse.ai chat assistants do not support synthetic tool-call output formats and will refuse mock function invocations.
Therefore, autonomous agent modes that require tool_calls for file/CLI execution are not supported.
However, all conversational, coding, reasoning, image generation, and video generation endpoints are fully functional and supported.
If a client sends a tools parameter, the proxy gracefully ignores it and completes normally as regular text.

System Settings & Storage Optimization

Configure media storage, automated cleanup rules, and API security. Saved directly to .env.
💡 Recommended: TmpFiles.org. Generated images and videos are uploaded to tmpfiles.org and served via direct download links. Files automatically expire after 48 hours, keeping your VPS lightweight without filling storage. Falls back to local disk automatically on upload timeout.
Old completed/failed tasks in tasks.json and local media files older than this threshold are purged automatically every hour by the background daemon.
Protects the dashboard and all /v1/* endpoints. Clients must supply Authorization: Bearer <key>.
